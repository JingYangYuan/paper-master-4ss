# check 模块参考库回查底座

本文件是 `check` 模块唯一顾问角色（`paper-check-reviewer`）的唯一参考回查源。角色卡仅保留指针行 `参考库回查: base=check-2026.10.24; tier=T2; 判据=…; 缺口=…`。

## B1 核心摘录（≤1200 字，主流程注入用）

`check` 模块从编辑部与审稿人视角评估稿件是否具备进入投稿整备的条件，并输出可执行的修改指令与退回目标。本模块不自行补建证据、不直接改写正文，也不替代 `submission` 的 Word 导出与投稿包整备。

10 维审稿分工与退回映射固定为：选题/创新 -> `design`/`lit`；标题、摘要、关键词、引言 -> `write`（或 `outline`）；正文 -> `outline`/`analysis`/`write`；结尾 -> `write`；引文注释 -> `lit`/`submission`；技术规范与投稿适配 -> `submission`。检查清单按三组读取：A 组（题摘关键词引言：`ch02`/`ch04`/`ch05`/`ch06`/`ch12`）、B 组（正文结尾：`ch06`/`ch07`/`ch08`）、C 组（引文技术规范：`ch09`/`ch10` + `cheatsheet`）。

严重度限定三级：**阻断**仅适用于学术诚信、事实/引文错误、核心证据缺失或论证闭环断裂；**重要**适用于显著损害创新表达、结构、可读性或期刊适配的问题；**优化**适用于不阻断投稿的表达与技术改进。总体结论限定四值之一：`可进入投稿整备`、`小修后进入投稿整备`、`大修后复审`、`不建议当前投稿`，且须与问题矩阵严格对应。

缺失原始引文或期刊公开规则时一律标注「待核验」，不得升级为违规结论；未获取目标期刊公开要求时写 `期刊特定核验: 未执行`，不得虚构栏目偏好或录用概率。

问题矩阵固定九字段：`check_id`、检查维度、原文位置/证据、依据、严重度、诊断、修改动作、退回模块、复核标准。修订后须沿用原 `check_id` 与同一复核标准复审。

## B2 判据条目

C01 输入与限制声明：报告开头明示被检稿件范围、可核验的期刊规则与已知缺口。

C02 十维全覆盖：选题/创新、标题、摘要、关键词、引言、正文、结尾、引文注释、技术规范、投稿适配十个维度逐一给出结论。

C03 严重度分级规范：仅诚信、事实/引文、核心证据与论证闭环可判 `阻断`，其余最高判 `重要`。

C04 四值结论约束：总体结论仅取 `可进入投稿整备` / `小修后进入投稿整备` / `大修后复审` / `不建议当前投稿`，并由问题矩阵支撑。

C05 缺证标注「待核验」：缺少引文原文或期刊规则时标注「待核验」，不推断违规。

C06 期刊适配边界：仅核验用户提供或可抓取的公开规则；缺失时标注 `期刊特定核验: 未执行`，不作录用概率预测。

C07 问题矩阵九字段完整：`check_id`、检查维度、原文位置/证据、依据、严重度、诊断、修改动作、退回模块、复核标准齐全。

C08 退回路径精确：每条问题指明退回模块（`design`/`lit`/`outline`/`analysis`/`write`/`submission`），不在 `check` 内直接改稿。

C09 复核标准可执行：每条问题具备可判定复核标准，修订后按原 `check_id` 复审。

C10 A 组（题摘关键词引言）门槛：按 `ch02`、`ch04`、`ch05`、`ch06`、`ch12` 规范核查。

C11 B 组（正文结尾）门槛：按 `ch07`（五类结构与十六种缺憾）及 `ch08`（结尾六类型与闭环三条）核查。

C12 C 组（引文技术规范）门槛：按 `ch09`（五项原则十项规定与转引链）及 `ch10`（八类技术细节）核查。

C13 创新可见度：评估题目、摘要与引言是否能让编辑快速识别研究问题与核心贡献，不达标至少判 `重要`。

C14 论证闭环：核查「问题—论点—证据—结构—结尾」闭环，结尾不得新增未经论证的声称。

C15 诚信与来源可追溯：核查引文可追溯性、转引链完整性与题录真实性。

C16 职责边界遵守：不直接改稿、不虚构期刊偏好、不作数值化录用预测、不替代 `submission` 或前序证据生产。

C17 保留分歧：与用户或前置模块意见不一致时保留分歧与未采纳理由。

C18 可追溯要求：判断指向具体章节条款、原文位置或期刊公开要求；缺失标「待核验」。
