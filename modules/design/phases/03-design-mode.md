# Phase 03：DESIGN 模式 — 理论锚点向研究设计蓝图转化

本阶段将既定理论锚点与核心研究问题转化为可执行的研究设计蓝图。报告文件首部须明确写入 `research_orientation` 与 `analysis_required: true|false`（混合取向须另写明主次路径及互证关系）。未选择实证取向时，不强制要求变量操作化、统计功效、回归模型或预分析计划（PAP）。

## 顾问派发规范

设计蓝图初稿形成后，仅针对材料/方法可行性、期刊适配、概念/规范/文本边界或反例风险选派最少必要顾问（无实质风险时记录 `agent-skip`）。派发前须由主流程读取对应参考文件内容并嵌入 prompt 末尾的 `## 参考库内容（主流程已预注入）` 段落：
- `method-consultant`：`references/method-feasibility.md` + `references/design-essence.md`；
- `positioning-consultant`：`phases/03-design-mode.md` + `master/output-protocol.md` + `references/argument-standards.md`（理论贡献类型）；
- `critical-review-consultant`：`phases/05-quality-gates.md` + `references/design-essence.md`（理论—方法对齐检查）；
- `theory-consultant`：`frame_locator.py --keywords` 输出 + 候选 `frame/theory-frameworks-*.md` 指定 `read_ranges` 片段。

意见与综合结论写入 `paper-workspace/_logs/agents/design-[YYYY-MM-DD]/agent-synthesis-design-[YYYY-MM-DD].md`。

## 触发条件

- 用户选择 `design` 模式，或以「研究设计」「方法设计」「设计方案」「设计蓝图」为目标；
- 已通过 FRAME/STORM 取得理论锚点与核心 RQ，或属于 `FULL` 模式第三阶段。

## 输入要求与补缺规则

| 字段 | 是否必需 | 说明 |
|---|---|---|
| 核心研究问题 / 中心论题 | 是 | 来自 FRAME/STORM 或用户直接给出 |
| 理论锚点 | 是 | 核心理论框架与机制链条 / 概念框架 |
| 核心要素结构 | 是 | 实证路径为 `X -> M -> Y`；理论/规范/阐释路径为论题、竞争立场、材料与不可声称边界 |
| 数据/材料来源 | 推荐 | 调查数据、访谈、档案或经典文献范围 |
| 目标期刊与方法偏好 | 推荐 | 决定设计呈现格式与方法细节深度 |

若用户跳过 FRAME/STORM 直接进入 `DESIGN` 且缺少理论锚点、核心 RQ 或材料来源，须先使用 `frame_locator.py` 完成初筛并询问用户是否补跑 FRAME/STORM，未确认前不得无依据生成设计蓝图。

## 执行流程

### Step 1：理论锚点确认与链路图示

输出「锚点确认卡」（写明 `research_orientation`、核心问题或中心论题、理论框架、核心机制或论证链、数据/材料来源、竞争立场、目标期刊与不可声称边界），并按 `master/output-protocol.md` 绘制理论—方法链路 Mermaid 图及 2–4 条中文解释：

```mermaid
flowchart LR
  T[理论锚点] --> RQ[核心问题/中心论题]
  RQ --> V[要素/材料结构]
  V --> D[数据/文献来源]
  D --> M[识别/论证路径]
  M --> PAP[执行与边界说明]
```

### Step 2：按研究取向生成研究设计

#### A. 实证取向（含混合取向的实证部分）

1. **范式与识别策略选择**：依据研究目标（因果效应、机制检验、过程追踪、意义建构、三角验证）与数据结构（面板 FE/DID/事件研究、截面+IV/2SLS、断点 RDD、重复截面队列 DID、质性过程追踪/比较案例）匹配识别策略与所需假设。
2. **变量操作化**：建立「理论概念 -> 操作化变量 -> 数据来源 -> 测量方式 -> 信效度依据」对照表。
3. **统计功效与样本评估**：明确预期效应量依据、所需样本量、显著性水平（`α = 0.05`）与统计功效要求（`1 - β ≥ 0.80`）。
4. **稳健性检验方案**：针对遗漏变量（Oster bounds/系数稳定性）、测量误差（替代指标/潜变量）、样本选择（Heckman/匹配）、反向因果（滞后项/IV）及竞争理论（竞争假设/rival 变量）设计检验方案（覆盖 ≥ 4 类威胁）。

#### B. 概念 / 解释理论、规范理论与思想史 / 文本阐释取向

- **概念/解释理论**：构建完备概念账本（工作定义、必要条件、正例、边界例、反例、相邻概念区分）、理论整合机制与 Toulmin 六要素论证链。
- **规范理论**：分别陈述事实前提、价值前提与可行性前提，界定评价标准、原则冲突与代价权衡，并以反例检验制度正当性边界。
- **思想史/文本阐释**：明确一手文本与版本选择、作者/行动者语境、解释单位与阅读规则、理论谱系及至少一种竞争诠释的对比处理。
- **理论—经验混合**：同时阐明理论部分与经验部分各自解决的问题、先后顺序、互证逻辑及互不替代边界。

### Step 3：理论—方法一致性七项核查

逐项评估并标注「通过 / 需调整 / 不通过」：

| 核查项 | 评估标准 | 常见错配修正 |
|---|---|---|
| **本体论对齐** | 理论认识论立场与方法/论证路径是否一致 | 调整方法路径或更换理论框架 |
| **机制/核心论证检验** | 能否检验指定机制或中心担保而非仅停留在表面关联 | 补足中介变量或核心担保支撑 |
| **边界条件覆盖** | 是否纳入理论边界条件、调节变量或反例范围 | 增设调节检验或范围限定 |
| **竞争理论区分** | 能否有效区分主理论与竞争理论/竞争诠释 | 引入竞争预测变量或竞争诠释对照 |
| **发表体例适配** | 是否符合目标期刊或学位论文的方法与论证偏好 | 按目标体例调整证明重心 |
| **分析层次匹配** | 理论命题与测量/材料层次是否一致（个体/组织/制度/国家） | 改用多层模型或校准命题层次 |
| **时间维度匹配** | 设计时间跨度或历史语境是否匹配理论时间假设 | 延长窗口、引入滞后或限定历史断面 |

### Step 4：输出 DESIGN 报告与日志

保存至 `paper-workspace/01-design/design-report-[slug]-[date].md`。文件头部须含：
- `research_orientation: <实证|概念/解释理论|规范理论|思想史/文本阐释|理论—经验混合>`
- `analysis_required: <true|false>`

报告正文按取向包含对应章节（理论锚点、研究设计概览、变量操作化或概念/前提/文本方案、实证模型或论证结构、功效分析或材料充分性、七项对齐检查、PAP 概要或竞争反驳应对、下游交接说明）。同步记录至 `paper-workspace/_logs/process-log-design-[YYYY-MM-DD].md`。

## DESIGN 质量自检

- [ ] 首部已写明 `research_orientation` 与 `analysis_required`
- [ ] 理论锚点、核心问题与材料来源清晰可追溯
- [ ] 实证路径已完成变量操作化、识别匹配、功效评估及 ≥ 4 类稳健性方案；非实证路径已完成对应概念/前提/文本与竞争反驳设计
- [ ] 理论—方法对齐七项核查全部评估，无未处理的「不通过」项
- [ ] 已明确不可声称边界与下游交接模块
