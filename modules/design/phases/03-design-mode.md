# Phase 03: DESIGN 模式 — 理论 → 研究设计蓝图

> **取向覆盖条款（优先于本文件其余默认项）**：锚点确认卡先写研究取向、核心问题或中心论题、材料、竞争立场和不可声称内容；直接进入 DESIGN 缺锚点或材料时询问是否补跑 FRAME/STORM。实证路径沿用变量、识别、功效和稳健性；概念/解释路径使用概念账本、理论整合与 Toulmin 链；规范路径使用事实/价值/可行性前提、标准、原则冲突、反例和制度含义；阐释路径使用文本/档案范围、版本、语境、阅读规则、谱系与竞争诠释；混合路径说明理论与经验问题、互证、顺序及不可替代证据。顾问由具体风险选择。`design-report` 首部必须写 `research_orientation` 与 `analysis_required: true|false`（混合另写主/次路径及关系）；未选实证路径不要求变量、功效、模型或 PAP。

## 顾问派发闸门

研究设计蓝图初稿形成后，按材料/方法、期刊、概念、规范、文本、反例或交接风险选择最少必要顾问复核。意见进入 `agent-synthesis-design-[YYYY-MM-DD].md`；无实质风险时记录 `agent-skip`，不因取向或固定人数强制派发。

**派发前主流程必做：参考库内容预注入。** Agent 子进程无法直接访问本 skill 目录。派发每个 agent 前，主流程必须 Read 对应参考文件并将实际内容注入 agent prompt：

| Agent | 派发前必注入文件 |
|-------|----------------|
| `method-consultant` | `references/method-router.md`（定量方法路由）+ `references/identification-strategies.md`（识别策略）+ `references/design-essence.md`（操作化、功效分析、稳健性方案） |
| `journal-fit-consultant` | `phases/03-design-mode.md`（输出规范、报告结构）+ `master/output-protocol.md` |
| `critical-review-consultant` | `phases/05-quality-gates.md`（L0-L4 门控定义）+ `references/design-essence.md`（理论-方法对齐七项检查） |
| `theory-consultant` | `frame_locator.py --keywords` 输出 + 候选 `frame/theory-frameworks-*.md` 的 `read_ranges` 区间内容 |
| `field-consultant` | 候选框架的学科位置与现实意义条目 + `references/theory-contribution-types.md` |

注入格式：在 agent prompt 末尾追加 `## 参考库内容（主流程已预注入）` 段落。

## 触发条件

- 用户明确指定 `design` 模式
- 用户关键词: `研究设计`, `方法设计`, `设计方案`, `设计蓝图`
- 用户已从 FRAME/STORM 获得理论锚点和 RQ
- 用户在 FULL 模式的第三阶段

## 输入要求

| 字段 | 必需 | 说明 |
|------|------|------|
| 研究问题 (RQ) | 是 | 从 FRAME/STORM 输出中选定的核心 RQ，或用户直接提供 |
| 理论锚点 | 是 | 核心理论框架及其机制链条 |
| 变量初步指定 | 是 | X → M → Y 的结构 |
| 数据来源 | 推荐 | CFPS/CGSS/CHARLS/自采数据/无 |
| 目标期刊 | 推荐 | 决定方法部分的格式和深度 |
| 方法偏好 | 否 | 定量/质性/混合方法 |

## 输入获取优先级

1. 从先前的 FRAME/STORM 报告中提取 (如果在同一会话中)
2. 要求用户指定 (如果直接进入 DESIGN 模式)
3. 如果用户跳过 FRAME/STORM 直接进入 DESIGN，先询问用户是否补跑 FRAME/STORM；用户确认后再运行 Phase 01 的 Step 1-3 和必要的 STORM 精炼步骤，不得无故跳跃。

## 执行流程

### Step 1: 理论锚点确认

确认用户在 FRAME 或 STORM 模式中确定的理论框架和 RQs。

#### 确认清单

```markdown
理论锚点确认卡

研究问题: [核心 RQ，一句话]
理论框架: [学科 + 理论名称 + 核心主张]
机制链条: [X → M1 → M2 → Y]
变量结构:
  - X (自变量): [变量名 / 操作化方向]
  - M (中介): [变量名 / 操作化方向]
  - Y (因变量): [变量名 / 操作化方向]
  - W (调节): [变量名 / 操作化方向] (如有)

数据来源: [CFPS / CGSS / CHARLS / 自采 / 其他 / 待定]
目标期刊: [期刊名 / 待定]
方法偏好: [定量 / 质性 / 混合方法 / 待定]
```

同时必须按 `master/output-protocol.md` 输出理论-方法链路图：

```mermaid
flowchart LR
  T[理论锚点] --> RQ[研究问题]
  RQ --> V[变量结构]
  V --> D[数据来源]
  D --> M[方法与识别策略]
  M --> PAP[PAP概要]
```

图后用 2-4 条中文解释说明理论锚点、变量结构、方法选择和不可声称边界。

若用户直接进入 DESIGN 模式 (跳过 FRAME/STORM)，必须先确认已具备理论锚点、核心 RQ、变量结构和材料来源。缺任一项时，先由主流程提取 3-8 个框架定位关键词，再运行 `python3 scripts/frame_locator.py --topic "[研究主题]" --keywords "[AI提取关键词]"` 完成 frame 初筛，按脚本输出的 `read_ranges` 行号区间读取候选理论内容，并询问用户是否补跑 FRAME/STORM；未确认前不得直接生成研究设计蓝图。

### Step 2: 研究设计生成

在当前会话中执行以下设计步骤:

##### 2.1 研究范式选择

| 研究目标 | 推荐范式 | 核心方法 |
|---------|---------|---------|
| 因果效应估计 | 定量—准实验 | DID, IV, RDD, PSM, FE |
| 机制检验 | 定量—中介/调节 | SEM, 因果中介分析, 调节效应 |
| 过程理解 | 质性—过程追踪 | 深度访谈, 参与观察, 档案分析 |
| 意义建构 | 质性—解释主义 | 叙事分析, 现象学, 扎根理论 |
| 三角验证 | 混合方法 | 定量+质性 并行/序贯设计 |

##### 2.2 识别策略选择

根据数据结构选择识别策略:

| 数据结构 | 推荐策略 | 所需假设 |
|---------|---------|---------|
| 面板数据 (2+ 期) | FE / DID / 事件研究 | 平行趋势 / 严格外生 |
| 横截面 + IV | 2SLS / IV Probit | 相关 + 排他性 |
| 断点 | RDD (Sharp/Fuzzy) | 断点处随机 |
| 重复横截面 | 队列DID / 年龄-时期-队列 | 队列可比性 |
| 质性数据 | 过程追踪 / 比较案例分析 | 理论饱和度 |

##### 2.3 变量操作化

从理论概念到经验测量:

| 理论概念 | 操作化变量 | 数据来源 | 测量方式 | 信效度证据 |
|---------|-----------|---------|---------|-----------|
| [概念X] | [变量名] | [数据集/问题编号] | [量表/指标] | [Cronbach α / CFA] |
| [概念Y] | [变量名] | [数据集/问题编号] | [量表/指标] | [Cronbach α / CFA] |
| ... | ... | ... | ... | ... |

##### 2.4 功效分析

```bash
# 使用 Stata 或 R 进行功效分析
# 如需定量设计，推荐运行 power 命令
```

功效分析要素:
- 预期效应量 (基于先前文献或 pilot)
- 所需样本量
- 显著性水平 (α = 0.05)
- 统计功效 (1-β ≥ 0.80)

##### 2.5 稳健性方案

| 威胁 | 稳健性检验 |
|------|-----------|
| 遗漏变量 | Oster bounds / 系数稳定性检验 |
| 测量误差 | 替代测量 / 潜变量模型 |
| 样本选择 | Heckman / 倾向得分匹配 |
| 反向因果 | 滞后自变量 / IV |
| 竞争理论 | 竞争假设检验 / 包含 rival 预测变量 |

### Step 3: 理论-方法一致性检查

在研究设计完成后，进行理论-方法对齐检查:

#### 对齐检查矩阵

| 检查项 | 评估标准 | 通过 | 需调整 | 不通过 |
|--------|---------|------|--------|--------|
| **本体论对齐** | 理论的认识论立场 (实证主义/解释主义/批判主义) 是否与方法匹配？ | [ ] | [ ] | [ ] |
| **机制检验** | 设计是否能够检验理论中指定的因果机制 (而不仅仅是 X→Y 关联)？ | [ ] | [ ] | [ ] |
| **边界条件** | 设计是否覆盖了理论的边界条件和调节变量？ | [ ] | [ ] | [ ] |
| **竞争假设** | 设计是否能够区分理论预测与竞争理论的预测？ | [ ] | [ ] | [ ] |
| **发表范式** | 设计是否符合目标期刊的方法论偏好和发表范式？ | [ ] | [ ] | [ ] |
| **层次匹配** | 理论和测量的分析层次是否一致 (个体/群体/组织/国家)？ | [ ] | [ ] | [ ] |
| **时间维度** | 设计的时间框架是否匹配理论的时间假设？ | [ ] | [ ] | [ ] |

#### 常见对齐问题与修正

| 问题 | 症状 | 修正方案 |
|------|------|---------|
| 本体论错配 | 用定量的因果推断检验解释主义的理论 | 调整为质性方法 / 或更换理论框架 |
| 机制黑箱 | 设计只检验 X→Y，未涉及中介机制 | 增加中介变量测量和中介分析 |
| 边界遗漏 | 未包含理论的边界条件变量 | 增加调节变量，检验交互效应 |
| 竞争理论混淆 | 无法区分理论A和理论B的预测 | 增加 rival 变量，设计竞争假设检验 |
| 层次谬误 | 用个体数据推断组织层次的理论 | 改用多层次模型 / 或调整理论层次 |

### Step 4: 输出研究设计蓝图

保存到 `paper-workspace/01-design/design-report-[slug]-[date].md`

#### 报告结构

```
# DESIGN 报告: [研究主题]

## 1. 理论锚点
- 研究问题: [核心 RQ]
- 理论框架: [学科 + 理论 + 核心主张]
- 机制链条: [X → M1 → M2 → Y]
- 理论贡献类型: [新解释/新机制/新边界/新方法]

## 2. 研究设计概览
- 研究范式: [定量/质性/混合]
- 设计类型: [实验/准实验/观察研究/案例研究/...]
- 识别策略: [DID/IV/RDD/过程追踪/...]
- 数据来源: [数据集/自采方案]

## 3. 变量操作化
- 变量操作化表 (概念 → 变量 → 测量 → 信效度)

## 4. 实证模型
- 基准模型设定
- 机制检验模型
- 异质性分析模型
- 稳健性检验方案

## 5. 功效分析
- 预期效应量 + 所需样本量 + 功效计算

## 6. 理论-方法对齐检查
- 七项检查结果
- 修正建议 (如有)

## 7. 预分析计划 (PAP) 概要
- 假设列表
- 模型设定
- 多重检验校正
- 排除/包含标准

## 8. 下一步
- 论文写作建议
- 预注册建议
- 数据采集计划 (如需)
```
