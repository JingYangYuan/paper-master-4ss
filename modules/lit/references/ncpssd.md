# 中文检索：NCPSSD（国家哲学社会科学文献中心）

NCPSSD（`www.ncpssd.cn`，中国社科院主管）是**中文社科清单的定位入口**，地位相当于英文链里的 Crossref——但只到"定位 + 元数据 + 分级"为止。

先用三句话定性，免得用错地方：

1. **检索与元数据匿名可查**，不需要账号、cookie、签名。走的是站点自己的 XHR handler，返回结构化记录（题名 / 刊名 / ISSN / 作者 / 年份 / 摘要 / 落地页）。
2. **它给不了全文。** 记录里的 `pdfurl` 绝大多数指向 `nssd.org`，那是**已经停用、域名挂牌待售**的旧站：实测取回一律是 4 660 字节的 HTML 停放页，不是 PDF（2026-11 实测，18/18 条如此）。2025 年后的新记录多半连 `pdfurl` 都没有。**所以它不能当"中文的 OA 链"用。**
3. **全文出口仍是知网机构 IP**（见 `cnki.md`）。NCPSSD 的正确位置是知网链的**上游**：先把题名/刊名/年份/第一作者定准，再交给 `cnki_prepare.py` → `cnki_fetch_batch.mjs`。

一句话记法：**NCPSSD 负责"有没有、是哪一篇、什么级别"，知网负责"把字节拿回来"。**

## 一、能做什么 / 不能做什么

| 能力 | 结论 | 说明 |
|---|---|---|
| 按主题发现文献 | ✅ | 多词按 AND 组合，五个字段（题名/关键词/英文题名等）任一命中 |
| 定向某刊 | ✅ | `--issns 0577-9154`，ISSN 权威；格式错直接报错，不静默退化成全库 |
| 按时间找最新 | ✅ | `--order recency`（站点自身排序），与相关度序答案差异很大 |
| 中文顶刊分级 | ✅ | 内置 64 种公认 CSSCI 顶刊，命中置顶标 `tier1_cn_top` |
| 补全清单的刊名/年份/第一作者 | ✅ | 中文清单最常见的脏列就是这三样 |
| 直取 PDF | ❌ | `pdfurl` 已死；落地页是要登录的 JS 壳 |
| 判断"知网收没收" | ⚠️ 间接 | 知网看 `LY='刊名'` 记录数（见 `cnki.md` 三），NCPSSD 只能佐证"这篇文章确实存在" |

## 二、用法

```bash
python scripts/ncpssd_search.py "数字普惠金融 城乡收入差距"
python scripts/ncpssd_search.py "共同富裕" --order recency --limit 20
python scripts/ncpssd_search.py "最低工资" --issns 0577-9154        # 定向《经济研究》
python scripts/ncpssd_search.py "乡村振兴" --tier1-only             # 只跑内置 64 种顶刊
python scripts/ncpssd_search.py "..." --json out.json               # 原始结构化结果
python scripts/ncpssd_search.py "城市治理 数字化" --csv 中文清单.csv  # ← 接知网链
python scripts/ncpssd_search.py "基层治理" --download-oa ../下载     # 验 pdfurl 是否活链（多数 ×）
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `query` | 必填 | 空格分隔多词 = AND；短语要整体匹配就别拆词 |
| `--limit` | 10 | 1–50。上限 50 的理由是**详情补全才是耗时大头**：25 条 5.5s、50 条 9.3s、75 条 17.8s |
| `--issns` | 空 | 可多个，`dddd-ddd[dX]`；给错格式报 exit 2 |
| `--order` | relevance | `relevance` 找"这领域说了什么"，`recency` 找"最近出了什么" |
| `--tier1-only` | 关 | 只跑顶刊定向轮 |
| `--json` | — | 全量字段落盘（含 `snippet`、`has_pdf_url`） |
| `--csv` | — | 列名已对齐 `cnki_prepare.py`：序号/题名/第一作者/期刊/年份/文献类型/等级/ISSN/链接/PDF链接 |
| `--download-oa` | — | 逐个取 `pdfurl`，`%PDF` 魔数 + ≥20KB 才算数，落 `ncpssd_oa.csv` 清单 |
| `--no-detail` | 关 | 跳过逐条详情补全：请求数从 1+N 降到 1，批量扫库必用；代价是偶见缺 ISSN |
| `--min-interval` | 1.2 | 请求最小间隔（秒）；站点在挡时调到 3 |
| `--detail-workers` | 3 | 详情并发；调大更容易触发验证页 |
| `--no-wait` | 关 | 忽略上次留下的冷却记录（换 IP / 刚从浏览器验过） |

退出码：`0` 正常（含空结果）、`1` 后端故障**或被限流**（两者都**不等于没有文献**，stderr 会区分 `ncpssd_unavailable` / `ncpssd_throttled`）、`2` 参数错、`3` 缺 httpx。

也可以 `import ncpssd` 调 `search_ncpssd(query, limit=10, issns=(), order="relevance", enrich=True)`，返回 `NcpssdHit`（title / url / snippet / venue / year / authors / issn / pdf_url）；`enrich=False` 等于 CLI 的 `--no-detail`。

## 四、返回字段的语义（别望文生义）

| 字段 | 语义 |
|---|---|
| `tier` | `tier1_cn_top` 或 `null`。只有内置 64 种会标，其余不评级 |
| `issn` | 详情补全才有；用它做去重与核对，比刊名可靠 |
| `year` | 站点的 `publishdate` 常是 `1900-01-01` 占位（旧库导入遗留）。`_year_of` 已夹在 1901–2100，越界返回 `None` 再用 stub 的 `years` 兜——不加这道清洗会批量输出"1900 年的文献"，把按年份选渠道的判断直接带偏 |
| `has_pdf_url` | 只是"元数据里标了全文链接"，**不代表能取**（见下） |
| `is_open_access` | **恒为 `null`**。不要拿它当 OA 判据 |
| `landing_url` / `url` | 落地页，登录后可在浏览器里下载 |

## 五、为什么是这么实现的（都会影响你的结果）

1. **多词必须拆成独立 OR 组再 AND。** 整句塞进单字段会被 handler 当短语读：`共同富裕` 5 条 → 三个词并一句只剩 2 条。召回塌方且不报错。
2. **相关度序必须"省略 `sort` 字段"。** 站点 Solr 不认 `score|DESC`，显式传会静默退回默认序——看起来像"排序没生效"，其实是参数被吞。
3. **去噪靠 `creator`。** 结果行混着期刊介绍页等非文献条目（无作者），直接剔除；`<font>` 高亮标签剥掉。
4. **详情补全默认 3 路并发、单条 best-effort，并且"分波 + 见好就收"。** 一条补全失败保留 stub（题名 + 落地页仍可用）；一波里出现两条被限流就停止补全剩下的，宁可少摘要也不让一次检索在退避里挂十几分钟——这也是 `--limit` 卡 50 的原因。
5. **空结果与故障严格分离。** 真没搜到 → 空列表 exit 0；响应里没有 `data.rows` envelope / 连不上 → `backend_error` exit 1。**把"后端挂了"当"没有文献"会让整份清单静默缺章。**
6. **匿名 + 走系统代理。** httpx 保持 `trust_env` 开，TUN/代理环境变量照常生效；不需要额外 cookie。
7. **站改版即失效。** 报错提到 `data.rows envelope` 就是这个信号，需重新抓包校准 handler 路径。

## 六、实测坑

| 现象 | 真因 | 处理 |
|---|---|---|
| `pdfurl` 条条 4 660 B HTML、`not-pdf` | `nssd.org` 已停用（域名挂牌待售），全部指向同一停放页 | 别把 `[标称OA]` 当可下载；全文走知网/登录落地页 |
| 年份出现 1900 | `publishdate` 是占位符 | 已在 `_year_of` 夹到 1901–2100 |
| 加了关键词结果反而变少 | 站点把整句当短语 | 脚本已拆 OR 组；自己写查询时同理 |
| `--issns` 传了不带横线的 8 位 | 格式校验拒绝 | 必须 `dddd-ddd[dX]`；没有"宽松模式"是有意的 |
| 相关度排序"没生效" | 显式传了 `sort` 被吞 | 省略 `sort`（`--order relevance` 已如此） |
| `共 0 条` 但浏览器能搜到 | 站点排序/字段差异，或确实无收录 | 换 `--order recency`、减少关键词、去掉 `--issns` 再试一次 |
| 后端不可用 exit 1 | handler 形状变了 / 网络不通 | **不要**当成"没有文献"写进清单；先修渠道 |
| 大量文献是同一批作者同一年 | 顶刊定向轮把某专题的顶刊文章全捞上来 | 正常，说明这批就是顶刊集中区；要广度就关掉顶刊优先（`--issns ''` 或直接看全库轮） |
| 命中里多条题名一模一样 | 中文同一题名被多刊/多年反复用（实测搜「数字普惠金融 城乡收入差距」前 4 条中 3 条同名） | **不能按题名去重**；看落地页 `id`。进知网时必须带 `AU='作者'`，否则同名撞车 |
| `HTTP 200` 但正文是「访问验证」页、`JSONDecodeError` | iCloudWAF 限流（按 IP + 时间窗），不是接口改版 | 已由连接器识别并自动退避；想立刻恢复见「七」的 cookie 注入 |
| 一批里前几条正常、后几条摘要/ISSN 全空 | 详情补全被限流，剩下的保留检索行元数据 | 属预期降级；`--min-interval 3` 或 `--no-detail` 重跑 |
| 并发跑多个检索，全部立刻失败 | 限流状态是 IP 级，多个进程一起撞 | 连接器的冷却跨进程共享；别再手动并发起 N 个进程 |
| `--csv` 给的「第一作者」只有一个人 | 知网 `AU=` 只认单人；多人并列会搜不到 | 有意为之；要全作者看 `--json` 的 `authors` |

## 七、限流与人机验证（2026-11 起的实际形态）

站点前面是 iCloudWAF（响应头 `wzws-ray`、Cookie `wzws_cid`）。**访问一密，它不返回 429，而是返回 HTTP 200 + 一页「访问验证」HTML**（"请完成安全验证! IP: x.x.x.x / 点击此区域继续访问"）。这页会让 `response.json()` 抛 `JSONDecodeError`，旧实现把它归成"后端不可用"，现场看起来像站点挂了。

三个硬结论：

1. **UA 是硬门槛。** 无 UA / `python-httpx/x.y` 默认 UA 直接 403；浏览器 UA 或脚本自述 UA 才放行。连接器现在统一发浏览器 UA（`LITDOWN_NCPSSD_UA` 可覆盖）。
2. **重试必须带真实等待。** 旧代码"重试 2 次"之间不 sleep，等于毫秒级硬撞两下，验证页根本来不及过期——这就是"跑一批废一批"的直接原因。
3. **限流是按 IP + 时间窗的，且状态跨进程。** 并发起 8 个 `ncpssd_search.py` 会一起撞墙；验证页通常要等十几分钟到半小时自行解除，或在浏览器里点一下立刻解除。

连接器现在的做法（都在 `scripts/ncpssd.py` 里）：

| 机制 | 默认 | 说明 |
|---|---|---|
| 最小请求间隔 | 1.2s（±15% 抖动） | 跨进程共享，写在 `$TMPDIR/litdown-ncpssd/throttle.json`，用 `flock` 串行化；并发跑多个检索不会各自抢跑 |
| 递增冷却 | 30→60→120→240→480s，上限 900s | 连续失败逐级拉长，成功一次清零 |
| 验证页识别 | `访问验证` / `waf_click_verify` / `wzws-waf-cgi` | 识别后按限流处理，而不是当 JSON 解析失败 |
| 重试次数 | 5 | 撑过一轮半小时的验证页 |
| 详情并发 | 3 | 4 路并发会把瞬时速率顶到 10+/s |
| 连接复用 | 单例 session | 连带复用 `wzws_cid`，少一轮验证 |

环境变量 / CLI：

```bash
# CLI（最常用）
python scripts/ncpssd_search.py "外卖骑手" --limit 20 --min-interval 3 --detail-workers 2
python scripts/ncpssd_search.py "外卖骑手" --limit 50 --no-detail      # 只取检索行，1 个请求搞定
python scripts/ncpssd_search.py "外卖骑手" --no-wait                   # 忽略上次留下的冷却
```

| 变量 / 参数 | 默认 | 用途 |
|---|---|---|
| `--min-interval` / `LITDOWN_NCPSSD_MIN_INTERVAL` | 1.2 | 降速到 3 秒可显著降低触发概率 |
| `--detail-workers` / `LITDOWN_NCPSSD_WORKERS` | 3 | 调大只会更容易撞验证页 |
| `--no-detail` | 关 | 不补摘要/ISSN，请求数从 1+N 降到 1；大批量扫库必用 |
| `--no-wait` / `LITDOWN_NCPSSD_STATE=off` | 关 | 丢掉冷却记录（换了出口 IP 或刚从浏览器验过时用） |
| `LITDOWN_NCPSSD_COOKIE` | 空 | 注入浏览器里拿到的 `wzws_cid=…`，立刻恢复 |
| `LITDOWN_NCPSSD_STATE_DIR` | `$TMPDIR/litdown-ncpssd` | 冷却状态目录（多机共享可放 NFS/同一路径） |

**现场处置顺序**：① 先等（脚本会自己等）；② 想立刻恢复就浏览器开 `https://www.ncpssd.cn` 点一次"点击此区域继续访问"，把 `wzws_cid` 塞进 `LITDOWN_NCPSSD_COOKIE` 重跑；③ 还是不行就换出口 IP（WAF 按 IP 记）；④ 大规模扫库一律 `--no-detail`，只对最终要精读的那几十条开详情。

## 八、接到 lit-down 主流程上

**A. 已知中文清单 → 下载（最常用）**

```bash
# 1) 清单只有题名/作者，先补元数据、并给出顶刊等级与落地页
python scripts/ncpssd_search.py "题名 作者" --limit 5 --csv 补全.csv
# 2) 人工/脚本把 补全.csv 的题名/期刊/年份/第一作者 覆盖回原清单
# 3) 进知网链
python scripts/cnki_prepare.py --csv 中文清单.csv --out 工作目录
# 4) 见 references/cnki.md 八
```

**B. 没清单，先做主题检索**

```bash
python scripts/ncpssd_search.py "数字普惠金融 城乡收入差距" --limit 30 --order relevance --csv 候选.csv
python scripts/ncpssd_search.py "数字普惠金融" --order recency --limit 20   # 另一问：最近出了什么
python scripts/cnki_prepare.py --csv 候选.csv --out 工作目录
```

两问的答案差异很大，**别只跑一个**：相关度序回答"这个领域说了什么"，recency 回答"最近谁在写"。

**C. 判一篇中文文献到底存不存在**

知网 `TI='完整题名' AND AU='作者'` 命中 0 条时，先别写"查无此文"：用 NCPSSD 搜一次题名。NCPSSD 有而知网没有，多半是**整刊未入库**（见 `cnki.md` 三）；两边都没有，才是真没有。

## 九、故障对照

| 现象 | 处理 |
|---|---|
| `缺少依赖 httpx` exit 3 | `pip install httpx` |
| `参数错误：--limit 取值范围 1–50` | 真的只支持 1–50 |
| `参数错误：malformed issn` | 补成 `0577-9154` 格式 |
| `后端不可用：ncpssd_unavailable: ...data.rows...` | 站点改版；重抓 handler，别当空结果 |
| 检索变慢（单条 >0.3s） | 详情补全所致，降 `--limit`；不要并发堆高，站点是公共服务的 |
| 想批量跑几百条 | 分批（每批 ≤50）+ `sleep(1–2)`；这是检索接口，不是下载接口 |

## 十、合规与边界

只做检索与元数据。NCPSSD 全文需（免费）注册登录后在浏览器里下载，**本技能不代下载、不绕登录**。`--download-oa` 只是验证公开链接是否还活着，不是取全文通道。检索频率按公共服务对待，别并发扫库。
